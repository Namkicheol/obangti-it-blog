Claude Code가 뭔지 잠깐만 — 모르는 분들을 위해

Claude Code는 미국 AI 기업 Anthropic이 만든 AI 코딩 도우미입니다.

간단히 말하면 이런 거예요.
"회원가입 페이지 만들어줘" 하면 Claude Code가 실제로 코드를 짜줍니다.
"이 버그 고쳐줘" 하면 에러를 찾아서 직접 수정합니다.
"블로그 HTML 만들어줘" 하면 완성 파일을 뚝딱 만들어 줍니다.

놀라운 건 이걸 쓰는 데 코딩 지식이 거의 필요 없다는 거예요.
한국어로 시키면 됩니다. 영어로 시켜도 됩니다. 그냥 말로 하면 됩니다.

그런데 한 가지 문제가 있어요. Claude Code를 쓰려면 터미널이라는 환경을 거쳐야 해요. 그리고 그 과정에서 낯선 용어들이 쏟아집니다. 그게 첫 번째 벽이에요.

💡 현직쌤 팁

1. 터미널 — 그 검은 창의 정체

처음 Claude Code를 설치하려고 유튜브나 블로그를 보면 갑자기 이런 말이 나옵니다.

"터미널을 열고 이 명령어를 입력하세요."

터미널이 뭔데요?

터미널(Terminal)은 컴퓨터에 글자로 명령 내리는 도구예요. 마우스로 클릭하는 대신, 키보드로 명령어를 쳐서 일을 시키는 방식입니다.

맥북에서는 이렇게 열어요:

⌘ + 스페이스바 → "Terminal" 입력 → 엔터

열면 이런 화면이 나와요. 하얗거나 검은 창에 커서만 깜빡거리는 그 화면이요. 처음 보면 당황스럽지만, 사실 이게 전부예요. 여기에 명령어만 치면 됩니다.

왜 이게 필요하냐고요? Claude Code는 이 터미널 안에서 실행됩니다. 앱처럼 실행 파일을 더블클릭해서 여는 게 아니에요. 터미널에 `claude` 라고 치면 켜지는 구조예요.

처음엔 낯설지만, 1주일만 쓰면 익숙해집니다. 그리고 그 뒤로는 오히려 편합니다. 마우스보다 훨씬 빠르거든요.

⚠️ 주의
터미널에서 실수로 잘못된 명령어를 치면 파일이 삭제되거나 시스템이 꼬일 수 있어요. Claude Code가 알아서 조심해주긴 하지만, 기본 명령어는 의미를 이해하고 쓰는 게 안전합니다.

2. 명령어 5개 — 터미널에서 살아남는 최소 지식

터미널에서 자주 쓰는 명령어가 수백 개는 됩니다. 하지만 Claude Code 처음 세팅할 때 실제로 필요한 건 딱 5개예요.

하나씩 풀어볼게요.

cd (change directory) — 폴더 이동 명령어예요. 터미널은 항상 "지금 어떤 폴더 안에 있는지"가 기준이 돼요. 작업하려는 폴더로 먼저 이동해야 해요. 예를 들어 `cd Desktop`이라고 치면 바탕화면 폴더로 이동합니다. `cd ..`은 "한 단계 위 폴더로 올라가라"는 뜻이에요.

ls (list) — 현재 폴더 안에 뭐가 있는지 보여줘요. 파일 이름들이 주르르 나열됩니다. 맥의 Finder 창에서 파일 목록 보는 것과 똑같은데, 글자로 보여주는 거예요.

mkdir (make directory) — 새 폴더를 만들어요. `mkdir bibib-app`이라고 치면 'bibib-app'이라는 폴더가 생깁니다. Finder에서 "새 폴더" 클릭하는 것과 같아요.

pwd (print working directory) — "지금 내가 어디에 있어?"를 물어보는 명령어예요. 치면 `/Users/namgicheol/Projects` 이런 식으로 현재 위치를 알려줘요. 길을 잃었을 때 쓰면 됩니다.

open . — 점(.)이 "현재 폴더"를 뜻해요. 즉 지금 있는 폴더를 Finder로 열어달라는 명령입니다. 터미널과 Finder를 왔다 갔다 할 때 유용해요.

💡 현직쌤 팁
명령어를 외울 필요 없어요. Claude Code한테 "지금 어느 폴더에 있는지 알려줘"라고 하면 알아서 `pwd` 쳐줍니다. 명령어보다 이게 뭘 하는 명령어인지만 알아도 충분해요.

3. Git이랑 GitHub — 이름 비슷하지만 완전히 달라요

Claude Code 세팅하면서 이 두 단어가 꼭 나옵니다. 이름이 비슷해서 같은 거라고 생각하기 쉬운데, 엄연히 다른 개념이에요.

Git (깃)은 버전 관리 도구예요. 내 컴퓨터 안에 설치되는 프로그램입니다.

예를 들어볼게요. 소설을 쓴다고 생각해봐요. 오늘 5페이지 썼어요. 내일 3페이지 더 썼어요. 그런데 다음 날 "어, 어제 버전이 더 좋았는데?" 하는 상황이 생길 수 있잖아요.

Git은 그 변경 이력을 자동으로 다 기록해줍니다. "4월 28일 저장본", "4월 29일 저장본" 이런 식으로요. 언제든 이전 버전으로 돌아갈 수 있어요. 마치 게임의 세이브 포인트 같은 거예요.

코드는 조금만 바꿔도 전체가 망가질 수 있어서, 이 버전 관리가 정말 중요합니다.

GitHub (깃허브)는 그 기록을 인터넷에 올려두는 사이트예요. Git이 내 컴퓨터의 도구라면, GitHub는 그걸 클라우드에 저장해주는 서비스예요.

네이버 클라우드나 Google Drive에 파일 올려두는 것처럼, GitHub에 코드를 올려두면 어디서나 접근할 수 있고, 다른 사람과 함께 작업할 수도 있어요.

정리하면: Git은 도구, GitHub는 사이트. 둘 다 써야 합니다. Git으로 기록하고, GitHub에 올리는 거예요.

Claude Code가 만든 코드는 GitHub에 올려야 웹에서 볼 수 있어요. 이미지 파일도 GitHub에 올려야 블로그에서 불러올 수 있고요. 그래서 이 두 개는 꼭 알아야 해요.

💡 GitHub 계정이 없으신 분은 지금 만드세요
github.com 가서 회원가입하면 됩니다. 무료 계정으로 시작 OK예요. 이메일 주소만 있으면 됩니다.

4. 레포지토리와 CLAUDE.md — Claude Code의 심장

이제 Claude Code랑 가장 직접적으로 연결된 개념 두 개예요.

레포지토리 (Repository, 줄여서 repo)는 "프로젝트 폴더 한 개"라고 생각하면 쉬워요.

예를 들어 영어 단어 앱을 만든다면, 그 앱의 모든 파일이 담긴 폴더 하나가 레포지토리예요. GitHub에 올라가면 'namkicheol/english-app' 이런 식으로 주소가 붙어요. 누구 것이고(namkicheol), 어떤 프로젝트인지(english-app)를 슬래시로 구분합니다.

Claude Code를 실행할 때는 항상 "어느 레포지토리 안에서 실행하는지"가 중요해요. 터미널에서 레포지토리 폴더 안으로 이동한 다음에 `claude`를 치는 거예요.

그리고 그 레포지토리 폴더 안에 있어야 하는 특별한 파일이 하나 있어요.

CLAUDE.md는 Claude Code가 제일 먼저 읽는 안내장이에요.

Claude Code를 켜면 맨 처음 이 파일을 찾아서 읽어요. "이 프로젝트가 뭔지, 어떤 규칙으로 작업해야 하는지, 어떤 기능을 만들어야 하는지" 다 여기에 적어두면 됩니다.

한 번 잘 써두면 새 대화를 시작할 때마다 Claude Code가 맥락을 기억하고 있어요. "저번에 만들던 그 앱 말이야…" 하고 설명 안 해도 됩니다. CLAUDE.md가 다 알려주거든요.

초보자한테는 CLAUDE.md가 특히 중요해요. 여기에 "나는 코딩 초보야, 설명 쉽게 해줘"라고 적어두면 Claude Code가 그걸 기억하고 항상 쉽게 설명해줍니다.

⚠️ 주의
CLAUDE.md가 없어도 Claude Code는 실행됩니다. 하지만 없으면 매 대화마다 "이 프로젝트가 뭔지" 다시 설명해야 해요. 꼭 만들어두는 게 좋아요. Claude Code한테 "CLAUDE.md 만들어줘"라고 부탁하면 알아서 만들어 줍니다.

5. PRD랑 MVP — 기획자 언어 처음 보는 분을 위해

Claude Code를 쓰다 보면 AI도 아니고 코딩도 아닌, 기획·스타트업 용어가 튀어나오는 순간이 있어요. PRD랑 MVP가 대표적입니다.

PRD (Product Requirements Document)는 "제품 요구사항 문서"예요. 쉽게 말하면 설계도입니다.

IT 회사에서 새 기능을 만들기 전에 기획자가 쓰는 문서예요. "이 기능은 어떤 사람이 쓸 건지, 어떻게 작동해야 하는지, 어떤 화면이 필요한지" 다 적어두는 거예요.

우리 같은 바이브코더한테는 Claude Code한테 넘겨주는 "일 시키는 서류"라고 생각하면 됩니다. "이런 앱 만들어줘, 이런 기능 들어가야 해, 이런 사람이 쓸 거야" 하고 적어서 주는 거예요.

Claude Code한테 PRD를 주면 그걸 바탕으로 코드를 짜줍니다. 막연하게 "앱 만들어줘"보다 훨씬 정확하게 만들어줘요.

MVP (Minimum Viable Product)는 "최소 기능 제품"이에요. "일단 제일 핵심 기능 하나만 빨리 만들어보자"는 전략입니다.

예를 들어볼게요. 영어 단어 앱을 만들겠다고 결심했어요. 원래는 "단어 암기 + 퀴즈 + 오답 노트 + 레벨 시스템 + 소셜 기능"을 다 넣고 싶어요.

그런데 MVP는 이렇게 생각해요.

"일단 단어 암기 기능만 만들자. 나머지는 그 다음에."

왜? 처음부터 모든 기능을 완성하려다가 중간에 지쳐서 아무것도 못 만드는 경우가 훨씬 많거든요. MVP 먼저 만들어서 써보고, 반응 좋으면 기능을 추가하는 게 현실적인 전략이에요.

Claude Code 처음 시작할 때도 MVP 마인드가 중요합니다. "완벽하게 다 만들고 시작"이 아니라 "일단 핵심만 빠르게, 나머지는 나중에"가 맞아요.

💡 현직쌤 팁
PRD 쓰는 법도 Claude Code한테 물어보면 됩니다. "내가 이런 앱 만들고 싶은데, PRD 초안 써줘" 하면 알아서 형식에 맞게 만들어줘요. 기획 경험 없어도 AI가 도와줍니다.

보너스: bash / zsh — 그냥 넘어가도 되는 개념

터미널을 열면 프롬프트가 `%`로 시작하거나 `$`로 시작하는 걸 볼 수 있어요. 이게 어떤 쉘(shell)을 쓰는지에 따라 다릅니다.

쉘(shell)은 터미널 안에서 명령어를 해석해주는 프로그램이에요. 종류가 여러 개 있는데, 맥북 기본값은 zsh(Z쉘)이고 예전 맥에서는 bash(배쉬)를 썼어요.

솔직히 말하면 — 초보자한테는 거의 차이가 없어요. 우리가 쓸 명령어들은 bash든 zsh든 다 똑같이 작동합니다. 그냥 "아 이런 게 있구나" 정도만 알고 넘어가도 됩니다.

나중에 세팅하다가 "zsh: command not found"나 "bash: command not found" 이런 에러가 뜨면 그때 다시 찾아보면 돼요. 지금 외울 필요 없어요.

지금까지 8개 용어를 알아봤어요. 다 외울 필요 없습니다.

"아 이런 게 있구나, 이럴 때 이 단어 쓰는구나" 정도만 느끼셨으면 충분해요. 나머지는 실제로 Claude Code 쓰면서 자연스럽게 체득됩니다.

처음부터 다 알고 시작하려는 분들이 제일 늦게 시작해요. 모르는 채로 일단 켜는 사람이 6개월 뒤에 훨씬 앞서 있어요.

Claude Code는 실수해도 됩니다. AI가 다 수습해줍니다. 지금 이 용어들을 어렴풋이 아는 상태면 충분히 시작할 수 있어요.
